# PR16 — automatic café service, first playable slice

Advancing game time on Café now generates arrivals (PR15) and processes pending arrivals oldest-first. Each arrival group can occupy seats for the configured average visit duration. Capacity is computed from previously served groups with arrival times inside the visit window. A group without enough seats is marked NO_SEATS. A group with seats chooses one available menu product using a deterministic rotation; product recipe/finished-goods stock is checked before selling. The existing CompleteCafeSaleUseCase handles FIFO stock, revenue, IVA, COGS and balanced journal entries. The arrival status and sale persistence run in the same Room transaction. Insufficient stock across all products yields NO_STOCK. Previously pending arrivals are processed on app entry; processed arrivals are not sold twice. No new schema migration.

**Explicit simplifications:** One product per *group*, not per guest. Arrival time doubles as sale completion time; cooking/service queues are not yet simulated. Seat occupancy is derived from historical SERVED arrivals and average visit length, not a dedicated reservation/seat table. No customer preferences, waiting queue, employee capacity, spoilage, supplier deliveries or real-time auto clock. Manual +15m/+1h buttons remain until PR17.

**Test on existing save:** advance +15m within opening hours; see served group, a new order and revenue/COGS entries in Finance, and reduced stock. Reopen the app: no duplicate sales for processed arrivals. Advance through busy periods and check NO_SEATS if full. Run out of stock to observe NO_STOCK. Old journal entries must remain.
